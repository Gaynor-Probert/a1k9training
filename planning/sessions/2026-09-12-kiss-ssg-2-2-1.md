# Session — 2026-09-12: Upgrade to kiss-ssg 2.2.1 and adopt aliases and {{link}}

## Intent (captured at kiss-branch-open)

**Objective:** Move the site from kiss-ssg 2.1.0 to 2.2.1 and take up the two
2.2.x features it has a use for — `aliases` (so kiss writes `_redirects` and
can report a page removed or moved without one) and `{{link}}` (so an internal
link is resolved by page id at render and a dead one fails the build) — with
the build output otherwise byte-identical.

**Success criteria:**

- [ ] `package.json` asks for `^2.2.1`, the lockfile resolves it, and
      `npx kiss-ssg check --summary generate.js` is `ok` with 19 pages,
      0 failed and no `broken link:` line (baseline at open: 19 pages, 0 failed,
      570 internal references, none broken).
- [ ] `src/assets/_redirects` is deleted. Its 14 rules now live as `aliases`:
      7 on the course records in `src/models/courses/*.json`, 2 on the
      consultation records in `src/models/behavioural-consultations/*.json`,
      4 on the about records in `src/models/about/*.json`, and `/find-us/` on
      the contact `.page()` in `generate.js`.
- [ ] The generated `docs/_redirects` carries exactly those 14 sources, each
      as one `<old> <canonical> 301` line, targets identical to the hand-written
      file's (`/courses/puppy-socialisation`, `/about/`, `/contact/`, …).
      `report().redirects` shows `aliases: 14`, `collisions: []`,
      `removed: []`, `moved: []`. The report's asset count drops from 92 to 91.
- [ ] No hardcoded internal page `href` remains in `src/pages`, `src/layouts`
      or `src/partials`; every one is `{{link "<id>" canonical=true}}` (ids per
      `AIKB/site-map.md`: `index`, `contact`, `courses/index`,
      `courses/course/<slug>`, `behavioural-consultations/index`,
      `behavioural-consultations/consultation/<slug>`, `about/index`,
      `about/<slug>`). Asset hrefs (`/fonts/…`, `/favicon.ico`) stay as they
      are — `{{link}}` is for pages.
- [ ] `canonical=true` is mandatory on every `{{link}}`: this site is not
      `extensionLess`, so a bare `{{link}}` renders `/courses/bronze-obedience.html`,
      which Netlify's pretty-URL rule would 301 back to the slashless form and
      `qa:preview`'s redirect-free check would fail. The check diff proves the
      swap was lossless: after the `{{link}}` step every page is `=` except
      those that carried a slashless section href (`/courses`, `/about`,
      `/behavioural-consultations` — 4 occurrences at open); those are `~` and
      their only change is the trailing slash. Nothing else in any page moves.
- [ ] The URLs `generate.js` builds by hand (`SECTIONS[].url`, `ladderStep`,
      the breadcrumb child `url`) either go through the same id → served-path
      resolution or are left as they are with a comment saying why — decided
      at the first pulse once it is known whether the `link` helper is callable
      from another helper. Either outcome is acceptable; silent drift between
      the two is not.
- [ ] The five notes the record asks for exist and are stamped with the
      subject hash from `report().aikb.subjects`:
      `AIKB/notes/controllers/{about,behavioural-consultations,course,faqmapper}.md`
      and `AIKB/notes/pipeline/tailwind.md`. The check prints no `note …:` line.
- [ ] `CLAUDE.md`'s Deploy paragraph names `^2.2.1` and what the site now
      relies on from it (aliases → `_redirects`, `{{link}}`, the record under
      `AIKB/`). The `_redirects` sentence under Assets and caching is rewritten:
      the file is generated from `aliases`, not kept in `src/assets`.
- [ ] `.claude/settings.json` enables both `kiss-ssg@kiss-ssg` and
      `kiss-memory@kiss-ssg` (already staged in the working tree at open).
- [ ] Eyeball: `npm run qa` passes (page count, no-Bootstrap, SEO, snapshot,
      compare, axe), and `/pr-verify` against the deploy preview reports every
      `_redirects` rule answering 301 to the same target as before.

**Non-goals / out of scope:**

- No `.feed()` — no page on this site carries a date.
- No switch to `extensionLess`, no change to any served URL, no copy or
  design change.
- No controller refactor beyond what a note needs to describe; no change to

- Not fixing the CRLF/LF churn git warns about on every file; it is noise

**Expected shape:** planned — the destination is known from the 2.2.0

## Reflection (written at kiss-branch-close, 2026-09-12)

### Reflect — what the session was

A dependency upgrade that turned into an adoption exercise: kiss-ssg 2.1.0 → 2.2.1, plus the two 2.2 features this site had a use for (`aliases` and `{{link}}`) and the first knowledge-base record. It was **planned**: the open wrote ten criteria against the changelog and the page-id table before a line changed, and the one genuine unknown — whether `generate.js`'s hand-built URLs could share the `{{link}}` resolver — was named as a criterion with both outcomes acceptable and settled at the first pulse (`kiss.handlebars.helpers.link` is callable at render time; `linkTo()` wraps it). The shape served the work: four slices, each verified by a tree diff of `docs/` before it was committed. One framing error: the open predicted that only pages carrying a slashless section href would change, forgetting the navbar is on every page. The tree diff, not the hash diff, became the proof of losslessness, and the pulse log says so.

### Evaluate — how the human supervised the AI

Three dimensions discriminated this session.

**Pushback & steering** was the strongest. After the open the agent reported "intent captured, branch ready", and the operator asked "I can't see where you've used the new link method". That was exactly right: nothing had been built, and the report could be read as if it had. The question converted a planning artefact into the first slice. Two further questions — whether the site should go `extensionLess` for SEO (answer: no, every URL is already extension-free and a switch would 301 every inner page for nothing), and "any other 2.2.1 improvements we can leverage?" — were **learning engagement** of the right kind: conceptual, ahead of code, and each produced a decision rather than more code.

**Verification & ownership** was mixed. The operator ran the plugin commands themselves and asked for verification of each, and accepted the agent's before/after tree diffs as evidence for the byte-identical criterion. But the two "eyeball" criteria — the rendered navbar and breadcrumb after the `{{link}}` swap, and the deploy preview — were not looked at by a human; the first was covered by a mechanical diff, the second is pending a PR. All three pulses were run by the agent on its own cadence; the operator did not ask for one. The cadence held anyway, which is the point of the loop, but the intent to supervise sat with the skill rather than the person.

**Iteration discipline** was good: slices of 65, 14 and 5 changes, each with a build, a diff and a commit, and a check that stayed green throughout. One coordination hazard: the operator edited and staged files in the same working tree mid-branch, and the CLAUDE.md commit swept in a staged rename and an intro edit that were theirs. Intended, harmless, but not something either party chose.

**Harness leverage**: the kiss-memory loop was used end to end, AskUserQuestion settled scope with one question, the slow QA run went to the background. The operator kept the plugin toolchain itself current (marketplace update, kiss-memory install) before the work started.

Level: **Active supervisor.** Framed the work through the open, asked conceptual questions before accepting direction, caught the one moment the report outran the work, and verified through the agent's evidence. Not yet **agentic engineering lead**: no independent review pass, eyeball criteria delegated to diffs, and the shared working tree mid-branch.

### Feedback — recommendations for next time

- **Human — refresh `qa/baseline/content.json` in the same PR that changes copy or URLs.** PR #24 renamed `/find-us/` and added breadcrumbs, the ladder and forms without refreshing it, so the compare gate failed on master before this branch opened and was noise here. Next time: `npm run qa:baseline` is part of any content PR's checklist, not a master-side chore.
- **Human — do not stage or edit in the working tree the agent is committing from, or say so.** The CLAUDE.md commit carried two of your changes by accident. Next time: a worktree for parallel edits, or a one-line "I've staged X" before the agent's next commit.
- **Human — look at one rendered page per slice when a criterion says eyeball.** The navbar swap was proven by diff, but the preview criterion is still open. Next time: open the deploy preview and click the three section links before calling close.
- **Agent — when a criterion predicts which pages change, read the partial index in `AIKB/site-map.md` first.** The navbar is rendered by all 19 pages; the open's "4 occurrences" estimate counted template lines, not pages. Next time: state the predicted diff in pages, derived from the partial → pages table.
- **Agent — say "no site code has changed yet" when the open finishes.** The operator had to ask. Next time: the open's report ends with what has and has not been built.
- **Agent — backtick only full repository paths in notes.** The first draft of the notes produced four `dangling` findings from bare filenames and a bare extension. Next time: `src/models/about/gaynor-probert.json`, never the bare filename.
- **Agent — write multi-file prose with the file tool, not shell heredocs.** Two long heredoc commands failed on quoting in this session and each cost a turn — the second while writing this very reflection. Next time: Write per file, Bash only for the check and the commit.
