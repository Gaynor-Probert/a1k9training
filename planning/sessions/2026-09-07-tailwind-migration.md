## Architecture after migration

```
src/styles/site.css        Tailwind v4 entry (@import "tailwindcss"; @theme tokens; @layer components)
src/assets/css/site.css    generated by the kiss asset pipeline (gitignored), copied + hashed by kiss
src/assets/fonts/          self-hosted Buenard 700 woff2, font-display: swap, preloaded
src/assets/js/site.js      ~60 lines vanilla: nav disclosure, deferred video facade
src/assets/images/**       resized WebP at source, width/height known, srcset for heroes
generate.js                kiss config: assets.pipeline (tailwind), assets.hash, siteUrl, .sitemap()
qa/                        Playwright + Lighthouse harness, baseline JSON, gates per loop
```

kiss gains `config.assets.pipeline`: an ordered list of shell steps that run
before the asset copy (`run`), and optionally a long-lived `watch` command that
kiss spawns in dev mode and kills on `close()`. A failing step fails the build
and is named in the build report. This is how Tailwind plugs in without kiss
knowing what Tailwind is.

## Loops

Every loop ends with a Playwright gate I run myself. A loop that fails its gate
is re-worked before the next one starts. Agents own files, never the same file
twice in one loop.

### Loop 0 — Baseline (Sonnet)

- `qa/` harness: static server for a built site, screenshot script (18 pages ×
  375/768/1440), content extractor (visible text, headings, links, images,
  form fields), Lighthouse runner (mobile), axe accessibility scan.
- Capture the **before** from a snapshot of the Bootstrap build
  (`qa/.baseline-site`, gitignored): `qa/baseline/content.json`,
  `qa/baseline/lighthouse.json`, screenshots in gitignored `qa/out/baseline/`.
- Gate: harness runs end to end on the baseline; JSON committed.

### Loop 1 — kiss asset pipeline hook (Opus, kiss-ssg repo)

- `lib/pipeline.js`, `config.assets.pipeline`, wiring in `lib/kiss.js`
  (construction, `_replay`, `close`, report), `AIKB/pipeline.md`, CLAUDE.md
  table row, `llms.txt`, `README.md`, `types/` regenerated, unit + integration
  tests, `examples/10-asset-pipeline.js`.
- Gate: `npm run gates` green in kiss; a1k9 dev-mode Playwright test proves a
  template class edit reaches the browser through the pipeline's `watch` command.

### Loop 2 — Design system and shell (Opus)

- Tailwind v4 installed; `src/styles/site.css` with `@theme` tokens (palette,
  type scale, Buenard headings); layout, navbar (mobile disclosure, keyboard
  dropdowns), footer, hero, buttons, cards, callouts, FAQ as `details`.
- Bootstrap 3 CSS/JS, jQuery, fancybox, shims, `bootstrap-4.5.scss` and the
  `bootstrap` dependency removed.
- Gate: build passes; no request for any removed asset; zero console errors;
  nav usable at 375 and 1440 with mouse and keyboard; no horizontal overflow.

### Loop 3 — Images at source (Sonnet, parallel with Loop 2)

- `scripts/optimise-images.mjs` (sharp): every referenced image resized to its
  role (hero 1920 + 960 variant, content ≤ 900) and converted to WebP; logos
  with transparency kept as PNG but resized; manifest with dimensions written
  to `qa/images.json`. Unreferenced originals listed, not deleted.
- Gate: every referenced file exists, no image > 250 KB, manifest complete.

### Loop 4 — Page migration (Sonnet ×3 in parallel, file ownership by area)

- A: `index.hbs`, `layout-video.hbs`, deferred video facade, featurettes.
- B: `courses/*`, `partials/courses/**`, `faqs.hbs`, course models.
- C: `behavioural-consultations/*`, `about.hbs`, `partials/about/**`,
  `partials/behavioural-consultations/**`, `find-us.hbs` (Netlify form intact).
- Every `<img>` gets `alt`, `width`, `height`, `loading="lazy"` (hero eager +
  `fetchpriority="high"`). Model `caption-class` values become semantic.
- Gate per area: content parity with baseline (text, headings, links, form
  fields); zero Bootstrap 3 classes left (`qa/no-bootstrap.mjs`); axe serious
  or critical = 0; screenshots for eyeball.

### Loop 5 — SEO and speed (Sonnet, then Haiku sweep)

- `siteUrl`, canonical, `.sitemap()` replaces the 2015 static sitemap, meta
  descriptions on all 18 pages, Open Graph, LocalBusiness JSON-LD, `_headers`
  for immutable caching of hashed CSS/JS and images, `assets.hash: true`,
  self-hosted font with preload, `lang`, one `h1` per page.
- Gate: Lighthouse mobile ≥ 90 performance and ≥ 90 SEO/a11y/best practices on
  all pages; sitemap has 18 URLs; internal link crawl finds no 404.

### Loop 6 — Close

- a1k9: `README.md` updated (build, dev, QA commands, Netlify settings),
  `npm run build`, dependency on kiss pinned, commits pushed.
- kiss: docs in sync, gates green, branch pushed. No `/branch-close`, no PR

- Final report with before/after table and anything left open.

## Risks

- Tailwind's automatic source detection must not scan its own output or
  `docs/`: both gitignored, and `@source` set explicitly.
- Netlify must install devDependencies (`@tailwindcss/cli`) and run Node ≥ 22.12.
- a1k9 consumes the unreleased kiss hook via a pinned git dependency until
  `2.0.0-alpha.6` is published; swap to the npm version then.
- Lighthouse in a container is noisy; scores are taken as the median of 3 runs.
